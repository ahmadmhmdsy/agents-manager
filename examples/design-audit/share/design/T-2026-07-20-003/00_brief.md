# 00 Brief — Stride Audit

**Restated from master task** (see `../user-task.md`).

## Discovery answers (the 7 questions)

1. **Medium**: Mobile (iOS + Android).
2. **Audience**: PM + dev team (PM for prioritization, dev team for concrete fixes).
3. **Constraint set**: Audit only — no redesign. Severity ranking. Phased remediation.
4. **Artifact set**: Findings + severity matrix + remediation plan.
5. **Mode set**: AUDIT + EVALUATE.
6. **Scope tier**: Medium (8 screens, one app).
7. **Success criteria**: PM prioritizes in 1 hour. Dev team has actionable instructions.

## What this dispatch produces

- `01_research/design-audit-input.md` — what was audited
- `05_audit/findings.md` — detailed findings
- `05_audit/severity-matrix.md` — ranked priorities
- `05_audit/remediation-plan.md` — phased fixes

## What this dispatch does NOT produce

- New design or mockups (separate dispatches if redesign is approved)
- Component library changes
- Brand work
- Source code changes

## Re-entry

If findings are accepted, remediation is tracked by master. If findings are disputed, this brief holds the ground truth (what was audited) for re-audit.
