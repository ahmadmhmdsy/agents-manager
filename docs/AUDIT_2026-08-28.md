# `agents-manager` Project Audit — v0.24.0 (2026-08-28)

## TL;DR

The project has grown impressively over 24 minor versions (master + 9 specialists, templates, memory system, install pipeline, release workflow). But the rapid growth has left a long trail of **stale docs, version drift, dead/redundant code, and CI gaps**. The most critical issues:

1. The master agent's inline prompt only knows about 5 of the 10 specialists.
2. The `bin/` CLI version strings are frozen at v0.10/v0.11 while the project is at v0.24.0.
3. The root `README.md` advertises v0.16.0 with 6 agents; actual is v0.24.0 with 9.
4. `bin/` has zero tests; CI frontmatter validation covers only 7 of 14 SKILL.md files.

**Severity totals:** 5 CRITICAL, 7 HIGH, 18 MEDIUM, 20 LOW (50 findings).

## 🚨 CRITICAL — User-visible breakage

### C1. `master.prompt` in `opencode.jsonc` only knows **5 of 10** specialists

**File:** `opencode.jsonc:46` (inside `master.prompt`)

The literal string in the injected prompt:

```
Route user tasks through 5 specialists via the task tool:
  task(subagent_type="am-research" | "am-planning" | "am-design" | "am-coder" | "am-review", prompt=...)
```

But the project defines **10 agents** (master + 9 specialists): the prompt is missing `am-assets`, `am-investigate`, `am-ship`, `am-health`. Master `SKILL.md` describes them all, but the inline prompt doesn't. The LLM receiving this prompt won't dispatch to them unless the `SKILL.md` is read first — which the prompt itself doesn't guarantee in the boot path.

**Fix:** replace the 5-type list with the canonical 9 (or 10) specialist types; cross-reference to `agents_manager/SKILL.md` § "Your specialists".

### C2. CLI version strings frozen at v0.10/v0.11 — actual project is v0.24.0

- `bin/agents-manager` (bash): `VERSION="v0.10.0"` (line 6)
- `bin/agents-manager.py`: `VERSION = "0.11.0"` (line 18)
- `bin/standalone-installer/install.py`: `VERSION = "0.11.0"` (line 27)

`agents-manager version` will report `0.11.0` while the actual installed package is `0.24.0`. This is a release-process gap — no script updates these constants when a tag is shipped.

**Fix:** have `am-ship` (or a release prep step) grep-replace these constants from `VERSION`, OR read `VERSION` at runtime via `$SCRIPT_DIR/../VERSION`.

### C3. Root `README.md` is severely out of date

**File:** `README.md`

- Line 5: `Status: v0.16.0` (actual: v0.24.0)
- Line 3: badge `Release v0.16.0` (actual: v0.24.0)
- Line 9: `six specialist agents` (actual: 9)
- Line 44: TOC section `The seven agents` (actual: 10)
- TOC missing: v0.17.0 → v0.24.0 sections (8 entries missing)

**Fix:** sync `## What's new` sections, status line, and agent counts.

### C4. `CLAUDE.md` agent table is stale

**File:** `CLAUDE.md:25`

- Lists only 6 agents (research, planning, design, coder, review)
- Project has 10 (added investigate/ship/health since; design/assets added later)
- No `## What's new` section — file predates most of the system

**Fix:** refresh the table with all 10 agents and `Owns` columns.

### C5. `examples/README.md` is missing 5 of 8 examples

- Says "Three worked examples" but `examples/` has 8 folders
- Missing entirely: `design-audit`, `design-brand-identity`, `design-casestudy-quran`, `design-onboarding`, `design-responsive-web`

**Fix:** add a row per example with stack + demonstrates notes.

## 🔥 HIGH — Quality / architecture gaps

### H1. `bin/` has **zero tests**

**File:** `bin/` (entire directory)

- AGENTS.md acknowledges "There are no tests for `bin/` scripts — only `scripts/validate-frontmatter.py`"
- The standalone installer is 419 lines of network-downloading, GitHub-API-calling, file-extracting logic with **no test coverage**
- `bin/agents-manager` is 965 lines of bash + `bin/agents-manager.ps1` is 827 lines of PowerShell — all untested
- CI only does syntax-level linting (`shellcheck` + PowerShell parser), no functional tests

**Fix:** add at least one CI job per dispatcher that runs the `--help` / `--version` / dry-run paths on `ubuntu-latest` + a Windows runner.

### H2. CI frontmatter validation covers only **7 of 14** SKILL.md files

**File:** `.github/workflows/ci.yml:64-72`

Lists: `agents_manager/{SKILL,research,planning,coder,review,design}/SKILL.md` + `mavis-team`.

Missing from CI:

- `agents_manager/assets/SKILL.md`
- `agents_manager/investigate/SKILL.md`
- `agents_manager/ship/SKILL.md`
- `agents_manager/health/SKILL.md`
- `agents_manager/extract/SKILL.md`
- `agents_manager/chub-validate/SKILL.md`
- `.agents/skills/self-reflective-prompt/SKILL.md`
- `.agents/skills/verification-validation/SKILL.md`

A bad frontmatter push in any of those 8 SKILL.md files will not be caught.

**Fix:** extend the `validate-frontmatter` job to glob `agents_manager/**/SKILL.md` and `.agents/skills/**/SKILL.md`.

### H3. CI uses legacy shim scripts instead of the canonical dispatcher

**File:** `.github/workflows/ci.yml:148, 168`

- `install-dryrun` job calls `bin/install.sh` (legacy 3-line shim)
- `check-script` job calls `bin/check.sh` (legacy 4-line shim)

Both should call `bin/agents-manager install` and `bin/agents-manager check` — the canonical entry point. The legacy shims aren't exercised by CI's primary install path.

### H4. CI runs on `ubuntu-latest` only

AGENTS.md acknowledges this — `.ps1` and `.cmd` scripts can't be CI-linted. The ps-lint job installs PowerShell on Ubuntu to parse the `.ps1`, but `.cmd` files have no CI at all.

**Fix:** add a `windows-latest` matrix runner for at least the smoke test.

### H5. SKILL.md frontmatter `version:` is stale on all 10 files

All 10 specialist SKILL.md files declare `version: 0.20.0` (extract says `0.18.0`). Project `VERSION` is **0.24.0**. The version field hasn't been bumped in 4 minor releases. If anything reads this field to decide behavior, it's wrong.

**Fix:** when `am-ship` bumps `VERSION`, also rewrite the `version:` field in each `agents_manager/**/SKILL.md` frontmatter.

### H6. Three redundant dispatcher architectures for the same CLI

- `bin/agents-manager` — bash, 965 lines
- `bin/agents-manager.ps1` — PowerShell, 827 lines
- `bin/agents-manager.py` — Python wrapper, 382 lines

~2,200 lines of CLI logic to maintain for the same surface. AGENTS.md claims Python is "recommended (stdlib only, single dialect)" but it just hands off to bash/PS1 anyway — so you still need those runtimes.

**Fix:** pick one (likely Python) and port bash/PS1 logic into it; remove the others. OR mark the bash/PS1 versions as legacy/deprecated and remove from release ZIP in v1.0.

### H7. Triple-defer shim chain

`bin/agents-manager.sh` → `python3 bin/agents-manager.py` → `bin/agents-manager` (bash) on Unix. On Windows: `bin/agents-manager.cmd` → `python bin/agents-manager.py` → `powershell bin/agents-manager.ps1`. Three different runtimes in one invocation chain.

**Fix:** flatten. Either the `.sh`/`.cmd` shims call the dispatcher directly, or the Python wrapper does — not both.

## ⚠️ MEDIUM — Drift, inconsistencies, dead code

### M1. `.gitignore` has duplicate entries

**File:** `.gitignore:31-33, 49-51`

Listed under both `agents-manager v0.10.0` and `agents-manager v0.11.0`:

- `share/notes/02_secrets_*.md` (twice)
- `share/screenshots/` (twice)
- `share/notes/99_progress_*.md` (twice)

**Fix:** drop the duplicate `agents-manager v0.11.0` block.

### M2. `.gitignore` ignores files that are tracked

**File:** `.gitignore:13-23`

Lines like `.agents/python/`, `.agents/react/`, `.agents/shopify/`, `.agents/design/`, `.agents/agent/SELF_REFLECTIVE_*`, `research_doc/` etc. are in `.gitignore` but exist in the repo. `.gitignore` doesn't untrack — these were committed before the rule was added.

**Fix:** remove from `.gitignore` (they're tracked) or move to a separate `.gitignore.local` example.

### M3. `agents_manager/master/` has an incomplete folder structure

All other roles have `notes/{semantic,episodic,reflections}/` + `resources/` + `SKILL.md` + `rules.md`. **Master has only `notes/reflections/`** (2 files). Missing:

- `notes/semantic/`
- `notes/episodic/`
- `notes/README.md`
- `rules.md`

Plus `SKILL.md` lives at `agents_manager/SKILL.md` (top-level), not in `master/`. Inconsistent with the documented convention in master SKILL.md L94-104.

**Fix:** move `agents_manager/SKILL.md` into `agents_manager/master/SKILL.md`; create the missing subfolders + files.

### M4. `investigate/`, `ship/`, `health/`, `extract/` role folders are incomplete

These have `SKILL.md` + `rules.md` only. Missing `notes/` and `resources/` directories that older roles (research/planning/design/assets/coder/review) all have.

**Fix:** add empty `.gitkeep` subfolders, or remove the convention if it's not enforced.

### M5. `extract/SKILL.md` lacks the chub mandate

**File:** `agents_manager/extract/SKILL.md`

Every other specialist's SKILL.md has a `## Context-hub (v0.20.0+) — MANDATORY` section. Extract doesn't. Inconsistent with the v0.22.0+ rule that "every agent must validate external module/library/framework/SDK/API usage with chub".

**Fix:** add the same 4-line mandate + pre-write step.

### M6. `coder/rules.md` has misordered rule numbering

**File:** `agents_manager/coder/rules.md`

Rule ## 17 ("chub validation is structural") appears **before** rule ## 16 ("WARN register collaboration"). Numbering is out of sequence; confusing for cross-references.

**Fix:** swap the two sections, or renumber.

### M7. `agents_manager/memory/projects/` is empty

**File:** `agents_manager/memory/projects/` (only `.gitkeep`)

The memory system's "project scope" has zero content — the v0.13.0 memory protocol is being used only at the global scope. Either the project-scope feature is unused or the example project hasn't been seeded.

**Fix:** add a stub example (`README.md` + `.extract-config.yaml.example`) or remove the projects/ scope from the protocol.

### M8. `share/notes/00_trace_*.jsonl` files don't exist

**File:** `share/notes/`

The trace log protocol (v0.17.0+) requires `scripts/append-trace.py` to be called on every dispatch. No `00_trace_*.jsonl` files in the repo → the protocol is documented but not exercised.

**Fix:** either trace-protocol discipline isn't enforced (mark as deprecated), or the example trace file is missing.

### M9. `share/reports/README.md` is only 8 lines

The review bus is a critical artifact store; 8 lines of documentation is thin.

### M10. `share/handoffs/README.md` is only 30 lines

Same — minimal for the entry point of the inter-agent bus.

### M11. `cinematic-landing-kit-demo/README.md` references a missing path

**File:** `cinematic-landing-kit-demo/README.md:3`

Links to `../cinematic-landing-kit-main/cinematic-landing-kit-main/` — that directory does not exist.

### M12. `examples/design-casestudy-quran` has lessons.md/retrospective.md but no `share/` artifacts

Inconsistent with `examples/node-markdown-linter/` (which has full share/) — design examples don't follow the same demonstration pattern.

### M13. `templates/_blank/` is intentionally a stub

**Files:** `templates/_blank/{README,INDEX,tests/verify.sh,...}`

Heavily marked with TODO/placeholder language. Expected for a starter template, but verification (`tests/verify.sh` only 28 lines) is non-functional by design.

### M14. `scripts/backfill-research-metrics.sh` exists

Suggests historical metrics were lost and needed recovery — implies the metrics discipline was retroactively backfilled rather than captured from day one.

### M15. `CHANGELOG.md` is a 1,931-line monolith

No release-grouped sections; newest-on-top linear format. Hard to scan or query; no per-release summary table.

**Fix:** add a top-of-file summary table (version + theme + 1-line summary + date).

### M16. `AGENTS.md` line 5 confuses agent count

> "9 specialist agents are defined in `opencode.jsonc` (master + research + planning + design + assets + coder + review + investigate + ship + health)"

The parenthetical lists 10 items. Confusing arithmetic for readers; either say "1 master + 9 specialists" or "10 agents total."

### M17. `CONTRIBUTING.md` line 4 is stale

> "the 6 agent definitions" (actual: 10)

### M18. README root stability signal is mixed

> "API may change between minor versions until v1.0.0" — but at v0.24.0 the API has shifted significantly (chub gate, local overrides, context externalization, self-reflection). Users may overestimate v0.x stability.

## 🔍 LOW — Polish / maintenance

### L1. `bin/lint-design.sh` has no PowerShell parity

Advisory linter is bash-only; no `lint-design.ps1`. AGENTS.md acknowledges this.

### L2. `bin/release-zip.sh` is 132 lines, mostly shell-scripted

Same logic duplicated in `bin/release-zip.ps1`. Only one source of truth for release ZIP logic would be safer.

### L3. `share/templates/_archive/AUTHORING.md.pre-promotion` exists

Looks like a pre-promotion draft that was kept around. Either promote or delete — currently ambiguous.

### L4. No CI step validates `opencode.jsonc` agent/permission structure beyond existence

**File:** `.github/workflows/ci.yml:25-43`

Only checks every agent has `prompt` + `permission`. Doesn't validate:

- `permission: "allow"` is the only permission used (could mask an accidental `deny`)
- `prompt` mentions expected subagent types per role
- Frontmatter is consistent across agents
- Tools/allowed-tools lists are well-formed

### L5. `share/notes/_helpers/append_row.py` is 25 lines

Real implementation; OK. But the manifest discipline (v0.23.0+) relies on it being called correctly by every specialist — no enforcement.

### L6. `agents_manager/upstream-contrib/` has 3 patch proposals

Coupling to external `obra/superpowers` skills creates ongoing maintenance. The `obra-sync-reminder.yml` quarterly workflow opens an issue every quarter — fine, but adds a perpetual backlog.

### L7. `templates/cinematic-landing/INDEX.md` is 167 lines

Long index for the flagship template. Could benefit from a TOC anchor system or a shorter overview linking to detailed files.

### L8. Master SKILL.md L91 says "soft walls — enforced by OpenCode's permission layer"

**File:** `agents_manager/SKILL.md:91`

> "The walls (e.g. `am-research` cannot write code, `am-coder` cannot edit `agents_manager/**`) are enforced by OpenCode's permission layer, not by prose."

This is **outdated**. Since v0.5.0, walls are soft (`permission: "allow"` everywhere) and enforced by prose, not by OpenCode's permission layer. The first 90 lines of master SKILL.md contradict the v0.5.0+ architecture described 20 lines below.

### L9. Master SKILL.md says "5-question preflight" but lists 5 questions

**File:** `agents_manager/SKILL.md:407-413`

That's correct, but the name vs count was a `mavis-team` borrow and the 5 questions are mostly generic. No role-specific preflight questions.

### L10. `share/notes/` has 100+ historical files

Mostly task artifacts from T-2026-07-* series. No archive policy. The `progress_<id>.md` files are gitignored but the other notes accumulate.

### L11. No automated way to discover "what version is running"

Reading `VERSION` from the file is the only way. `bin/agents-manager version` will (per C2) report 0.11.0. No `--check-update` reliable answer.

### L12. `agents_manager/.gitignore` is one line

**File:** `agents_manager/.gitignore`

Just `.active-project`. Could include `.local.md.bak`, scratch dirs, etc. but is minimal.

### L13. `research_doc/` is gitignored but exists

**File:** `research_doc/`

Listed in `.gitignore` but `research_doc/README.md` and `research_doc/{decisions,overrides}/.gitkeep` are present. Local-only scratchpad in a tracked directory — confusing.

### L14. `agents_manager/research/resources/web-search-strategy.md` has 1 TODO

Plus 9 TODOs in `coder/rules.md` (mostly rule clarifications, not bugs).

### L15. `share/templates/` exists but only has `_archive/`

**File:** `share/templates/_archive/AUTHORING.md.pre-promotion`

The extract skill's protocol mentions writing proposals to `share/templates/drafts/**` (per extract/SKILL.md L48) but no drafts/ subdirectory exists.

### L16. `agents_manager/assets/notes/branch-decisions.md` exists but no other "notes"

**File:** `agents_manager/assets/notes/`

The assets role notes folder has only `branch-decisions.md` (no README, no semantic/episodic). Same structural gap as master (M3).

### L17. Several design examples have `share/messages/` but no master synthesis or final review report

`examples/design-onboarding/`, `examples/design-responsive-web/` etc. show mid-flight artifacts only — no end-state validation. Hard to know what "done" looks like for am-design.

### L18. `agents_manager/extract/SKILL.md` says "Agent-led, not CLI" — but the dispatcher surface includes no `extract` subcommand

The `bin/agents-manager` dispatcher has `install`, `update`, `check`, `doctor`, `uninstall`, `skills`, `release`, `lint` — **no `extract`**. Extraction is only available through the agent dispatch path.

### L19. README.md says `agents-manager install` is the entry, but `bin/install.sh` is still the documented fallback

Two entry points coexist; not migrated cleanly.

### L20. Several "v0.x.y" tags may not exist on GitHub

AGENTS.md says "release appears in <2 min" but no way to verify from the repo which tags exist locally — `git tag -l` would show.
