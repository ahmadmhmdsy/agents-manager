## My modifications to the upstream patch

The patch is excellent — 100% additive, opt-in by default, LLM-actionable, reversible. I made **one** modification:

### C2 fallback clause

The upstream patch assumed `browsermcp_*` tools would be available. Most downstream projects don't have browser MCP installed. I added a third "skip when" clause to C2:

> **No browser tool is available in this session** (master does not have access to `browsermcp_*`, OpenCode native browser, or any equivalent). In that case, log "browser preflight skipped — no browser tool in agent's tool set" in the reviewer's prompt and continue without visual reference. This is the most common case for downstream projects that haven't installed browser MCP.

Without this clause, projects without browser tools would dead-branch on the preflight. With it, the SKILL.md text is present and instructive for projects that do have tools, and silent for projects that don't.

## Where I agree with the upstream user entirely

The user's "What I recommend NOT to do" section is correct:
- **No new specialists** — agents_manager is correctly sized at 5. Pressure to add a fifth is usually a sign that existing rules are too vague.
- **No path renames** — keep all paths additive for easy reversion.
- **No auto-init git** — the prompt must stay opt-in; sandbox projects don't want git tracking.
